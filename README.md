# 微光旅伴 / Glimmer Companion

一个不使用第二个真实玩家的《饥荒联机版》AI 伙伴项目。

当前版本：`0.15.1`

"微光"是服务器内的非联网角色实体，不会占用额外玩家名额，也不会破坏“独行长路”的
单人服务器限制。DeepSeek 负责任务级规划，Lua 执行层负责实时寻路、战斗、采集、
制作、技能动作、安全撤退与状态持久化。

仓库地址：

```text
https://github.com/xiaolangmin-cloud/Glimmer-Companion
```

最新 Mod 包：

```text
https://github.com/xiaolangmin-cloud/Glimmer-Companion/releases/latest
```

## 快速开始

```powershell
git clone https://github.com/xiaolangmin-cloud/Glimmer-Companion.git
cd Glimmer-Companion
```

### 1. 环境要求

- Windows 10/11
- Python 3.10+
- 《饥荒联机版》
- DeepSeek API Key
- 可选：Codex CLI，用于让"微光"在缺少资料时执行只读联网研究

### 2. 配置 Key

Key 只从环境变量读取，不写入仓库或配置文件：

```powershell
[Environment]::SetEnvironmentVariable("DEEPSEEK_API_KEY", "你的Key", "User")
[Environment]::SetEnvironmentVariable("DEEPSEEK_BASE_URL", "https://api.deepseek.com", "User")
[Environment]::SetEnvironmentVariable("DEEPSEEK_MODEL", "deepseek-chat", "User")
```

设置后重新打开 PowerShell。

### 3. 安装 Mod

把仓库中的 `mod` 目录复制到：

```text
<你的饥荒安装目录>\mods\codex_companion
```

目录内应直接看到：

```text
modinfo.lua
modmain.lua
scripts/brains/codex_companion_brain.lua
```

在游戏 Mod 设置中启用 `"微光"旅伴`，建议角色选择“与玩家相同”。

### 4. 启动控制器

直接运行：

```text
start_companion.cmd
```

或：

```powershell
python -m controller.main
```

控制器默认监听 `127.0.0.1:8765`。所有聊天和任务指令都在游戏聊天框中输入，
不需要前缀：

```text
跟着我
去打些蜘蛛丝
现在有多少蜘蛛丝
把这里记作家
今天怎么样
```

### 5. 选人窗口

启动控制器后，双击：

```text
open_character_selector.cmd
```

浏览器会打开本机的“微光旅伴·选择角色”窗口。默认选择麦斯威尔；点击角色后，
选择会保存到控制器的 `state/companion_character.json`，并在游戏内自动应用。
游戏运行期间切换现有微光时，会中断当前任务，并把微光的背包和装备丢在它脚下，
因此建议在基地或安全位置切换。

选人窗口由本地控制器提供，不需要把 Mod 改成客户端 Mod，也不要求其他客户端安装。
环境变量 `CODEX_COMPANION_CHARACTER` 可修改首次启动的默认选择，例如：

```powershell
[Environment]::SetEnvironmentVariable("CODEX_COMPANION_CHARACTER", "waxwell", "User")
```

### 6. 进入存档后自动启动控制器

双击一次：

```text
install_game_launcher.cmd
```

安装器会在桌面创建：

```text
Don't Starve Together - 微光
```

该快捷方式会自动查找 Steam 库中的联机版客户端，并使用联机版程序自带图标。

以后从这个桌面快捷方式启动联机版，而不是直接点 Steam 的“开始游戏”。快捷方式会
同时启动一个仅在本局游戏期间存在的轻量本地启动桥，再由它打开游戏。启动桥不是
控制器，不会在游戏主菜单阶段启动完整控制器。游戏没有运行时，启动桥和控制器都
不常驻。

玩家进入存档后，Mod 会在游戏聊天栏依次提示：

```text
[微光] 已进入存档，正在请求启动本地控制器。
[微光] 启动桥已接受请求，控制器正在启动并等待接口就绪。
[微光] 控制器连接成功，正在初始化微光和记忆。
```

只有在控制器健康检查通过后，Mod 才会生成微光。若控制器原本已经手动运行，Mod 会
直接连接，不会重复启动；若控制器由启动桥拉起，游戏关闭后会自动停止控制器。可运行
以下文件移除登录自启动、停止启动桥及其控制器：

```text
uninstall_game_launcher.cmd
```

启动桥使用原生 Windows 进程枚举，不反复启动 PowerShell。本局游戏期间启动桥工作集
约 30 MB、私有内存约 16 MB；进入存档后由它启动的 Python 控制器工作集约 35 MB。
退出游戏后两者都会停止。DeepSeek 网络请求只在玩家输入或重要任务事件时发生，不参与
逐帧模拟。

## 主要能力

## 设计约束

- "微光"是服务器内生成的非玩家幸存者，不建立客户端连接。
- "微光"使用真正的可玩角色预制体，默认与玩家当前角色相同；模组配置也可指定
  温蒂、薇尔逊、薇洛、沃尔夫冈、WX-78 等原生幸存者。
- 服务器仍保持 `max_players = 1`，兼容“独行长路”。
- 任务决策只有一个来源：DeepSeek 控制器；无任务跟随时，Lua 执行层只按固定规则
  自动进食、治疗和安全睡觉，不自行创建或改变任务。
- DeepSeek 只做任务级规划，不参与逐帧操作。
- Lua 执行层可在当前任务范围内自动寻路、走位、战斗、进食和选择下一个同类目标。
- "微光"是服务端永不休眠实体，并维持自身附近的独立行动区域，不依赖玩家靠近才继续执行。
- 没有任务、任务完成或租约到期时默认跟随玩家；明确说“在这里等”才保持原地。
- 默认跟随时会自主吃随身食物、使用治疗物品，并在条件合适时去附近帐篷恢复
  生命与精神。帐篷判断包含当前时段、剩余睡眠时间、预计恢复量、睡眠饥饿消耗、
  睡后安全饥饿线、帐篷耐久和附近危险；不会为了很少的收益浪费整晚饥饿。
- 自主恢复不会唤醒 DeepSeek。执行器会在出发、完成或因饥饿、时间、危险等原因
  放弃时直接通过游戏聊天栏说明；新的非跟随任务会立即叫醒微光并中断恢复。
- 支持远距离 `move_to` 和 `fetch_item`；卡住、找不到物品、背包满会作为明确事件上报。
- 支持把当前位置记录为“家/基地”等地标；地标按地面和洞穴分别持久保存。
- "微光"跨地面和洞穴时携带完整角色存档记录，包括生命、饥饿、精神、装备、
  背包物品的堆叠数、耐久、保鲜度与皮肤状态。
- 跨世界迁移时默认跟随玩家到达入口附近，并取消旧世界的战斗、采集或移动任务。
  玩家不需要先让"微光"进出洞穴，也不会在下次进入时被传送回远古区旧坐标。
- 控制器在意图下发前强制检查目标世界。DeepSeek 或手动命令试图让"微光"自行去
  另一个世界时，会改为 `hold/cross_world_forbidden`，记录
  `controller.cross_world_blocked`，并明确要求由玩家本人带"微光"过图。
- 与玩家选择相同角色时，会复制玩家当前技能树选择。
- 支持 `use_skill` 调用角色特殊动作、法术、特殊物品和可用装备动作。
- 支持制作、建造、种植/放置、耕地和显式装备切换。
- 支持 `collect_loot` 连续击杀来源生物、拾取指定掉落并交付玩家，例如蜘蛛丝。
- 用户明确安排的远距离收集任务可解除跟随距离限制；找不到目标时会扩大巡逻范围，
  默认不逐只播报，完成并交付后直接汇报总数。
- 远行任务开始和执行中都会检查饱食度与生命值。低于安全线时先吃背包食物；没有
  食物或生命过低则取消任务、返回玩家并在聊天栏说明原因。用户明确说“别管饥饿”
  或“务必去”时，任务会带安全覆盖标记继续执行，当前任务也不会因致命伤保护自动撤退。
- "微光"会持续把自身当前位置写入玩家共享地图探索数据，因此它开拓的区域会显示在
  你打开的地图上；玩家角色预制体自带的头像图标会保留并始终显示"微光"位置。
- 战斗会自动装备背包中可用的较高伤害武器与较高减伤护甲，远程武器使用标准攻击距离。
- 默认启用致命伤保护：下一次合理伤害估算足以击杀时，立即停战并撤回玩家身边。
  只有明确命令“死战到底”或“别逃跑”才关闭该保护。
- 完整配方、材料数量、附近箱子和资源位置会进入任务观察；复杂目标使用持久化
  多步骤计划，并可在缺少资料时调用 Codex 只读查询网络攻略。
- 任务匹配器会优先使用角色专属预案。当前已完成麦斯威尔的基础移动、蜘蛛丝收集、
  范围采集、简单制作和若干 Boss 策略卡；高置信度任务直接执行，不再消耗一次
  DeepSeek 调用。
- DeepSeek 不可用时执行器不会另起一套 AI；当前任务租约结束后默认回到跟随。

## 角色能力与生产

观察快照中的 `capabilities` 包含：

- `skills`："微光"已继承的角色技能。
- `skill_actions`：执行器允许调用的角色特殊动作白名单。
- `craftable_recipes`：当前已知且材料足够的配方。
- `known_recipes`：完整配方、材料需求、科技等级和角色技能要求。
- `inventory_counts`：背包与装备中各物品的实际总数量。

生产模式包括 `craft`、`build`、`deploy`、`plant`、`till`、`equip`、
`unequip`。角色特殊动作通过 `use_skill` 执行，并继续使用真实角色的动画、
资源消耗、动作失败原因和状态图。

## 架构

```text
游戏聊天
   │
   ▼
DST Mod ──观察/事件──► 本地控制器
   ▲                    │
   │                    ├─ 角色任务匹配器（本地、零模型调用）
   │                    ├─ 独立技能/聊天/世界记忆
   │                    ├─ DeepSeek 任务规划
   │                    └─ Codex 只读联网研究（按需）
   │                    │
   └──────意图/回复─────┘
```

- **控制器**：任务仲裁、DeepSeek 调用、角色预案匹配、记忆与日志。
- **Mod 执行层**：寻路、战斗、采集、制作、技能动作、安全检查和完整角色状态迁移。
- **DeepSeek**：只处理不确定的任务规划和对话，不参与逐帧移动或攻击。
- **Codex Research**：仅在本地技能库与观察不足时联网查询资料。

## 安全与隐私

- API Key 只从环境变量读取。
- `.env`、日志、SQLite 状态库、测试存档和版本压缩包不会提交到仓库。
- 玩家个人长期记忆库默认只读。
- "微光"攻略、聊天和世界记忆使用独立数据库，不写回个人记忆库。
- 跨世界必须由玩家本人带"微光"过图，控制器会阻止"微光"自行穿越世界。
- 默认启用低血撤退和远行生存检查；用户明确要求高风险执行时才可覆盖。

[Environment]::SetEnvironmentVariable("DEEPSEEK_API_KEY", "你的Key", "User")

## 记忆库

默认只读：

```text
%USERPROFILE%\.dsh\memory\vault
```

控制器会把 Markdown 文档索引到项目自己的 SQLite 索引文件，不修改原记忆。
只有用户明确要求记录新事实时，才按现有格式追加到 `chats/facts/`。

"微光"自己的技能攻略、聊天室、世界资源位置和任务计划写入独立数据库：

```text
dst_codex_companion\state\agent_memory.sqlite3
```

该数据库不会写回 `%USERPROFILE%\.dsh\memory\vault`，避免游戏攻略、Boss 打法和
闲聊内容污染整体长期记忆。

角色预案保存在 `config\playbooks\`。当前只有 `maxwell.json`，后续可按相同格式添加
其他角色。执行器无法完成的能力不会假装完成，而是向游戏聊天栏说明原因，并记录到
独立数据库的 `capability_gaps` 表；可访问 `GET /gaps` 查看尚未处理的缺口。

## 启动控制器

```powershell
python -m controller.main
```

默认监听 `127.0.0.1:8765`。

控制器窗口只显示运行状态、游戏事件和"微光"回复，不提供聊天输入。所有交流都在
游戏内聊天框完成，不需要前缀：

```text
跟着我
去打那只蜘蛛
今天怎么样
把这里记作家
```

你输入的每一句普通聊天都会交给"微光"。DeepSeek 根据内容判断是任务指令还是
普通对话，两者共用同一段聊天记忆；表情、系统公告和其他非文字事件不会误触发。
"微光"回复同时显示在游戏聊天栏、角色对话气泡和控制器窗口中。

语音识别和 TTS 入口已经关闭并移除。

## 任务日志

控制器会把任务开始、20 秒级移动进度、取得物品、战斗结果、完成、失败、
阻塞、模型错误和"微光"回复写入：

```text
dst_codex_companion\state\logs\companion-latest.log
```

同目录下另有按日期保存的 `companion-YYYY-MM-DD.jsonl`。控制器窗口会同步显示
`[日志]`；也可以访问 `GET http://127.0.0.1:8765/logs?limit=100`。
最近事实会作为 `journal` 提供给 DeepSeek，使主动闲聊可以自然地提到刚发生的
趣事，同时任务完成汇报必须来自真实的完成事件。

自然语言指令示例：

```powershell
$body = @{ text = "你去把家里的作物收一下" } | ConvertTo-Json
Invoke-RestMethod -Uri "http://127.0.0.1:8765/instruction" `
  -Method Post -ContentType "application/json; charset=utf-8" `
  -Body ([Text.Encoding]::UTF8.GetBytes($body))
```

模型只在收到指令或任务完成、失败、重大事件时调用。普通跟随、移动、
自动战斗和采集不会逐帧请求 DeepSeek。

## 独行长路的边界

同一张地图内，"微光"可以离开玩家独立行动。进出地面和洞穴仍然受“独行长路”
的单人优化限制：该 Mod 只运行玩家当前所在世界，因此"微光"不能留在已经关闭的
另一张地图里继续真实采集或战斗。

现在玩家切换世界时，"微光"会随玩家迁移。实现上会把"微光"的完整实体存档嵌入玩家
的迁移存档，在新世界恢复为同一份持续档案；旧世界实体随即停止并移除。玩家先
进入或先离开都不会把"微光"遗留在关闭的世界中。

## 实机验证状态（2026-11-11）

已在独立复制的本地测试世界中确认：

- 真正角色预制体会作为非联网幸存者生成，服务端玩家列表仍只有玩家本人。
- "微光"可持续向控制器发送位置、周围实体、背包和世界状态快照。
- `follow` 能跟随玩家移动；玩家距离较远时会重新寻路靠近。
- `harvest` 能走到玩家视野外的目标处完成采集，并上报
  `game.task_started` 和经过验证的 `game.task_complete`。
- 任务完成后默认回到 `follow`，只有明确要求等待时才进入 `hold`。
- `move_to` 能在数秒内到达指定坐标并上报完成。
- `/chat` 只产生对话回复，不替换当前任务。

自主恢复链路已在无窗口专用服务器确认：

- 微光会评估剩余睡眠时间、预计三维收益和饥饿代价；饥饿不足以安全睡完整晚时，
  会在游戏聊天栏说明具体消耗、睡后剩余值和最低保留线。
- 条件满足时会走到帐篷并进入真实睡眠，按原版规则持续消耗饥饿、恢复生命与精神，
  天亮后自动醒来并汇报最终状态。
- 睡眠期间通过控制器收到新的 `hold` 任务时，微光会立即醒来、清除恢复状态并接受
  新任务，不会继续睡到天亮。
- 自动进食会使用原版 `EAT` 动作，真实消耗背包食物并提高饥饿；材料足够时会把
  饥饿恢复到安全线并汇报最终数值。

制作与建造状态机也在同一轮回归中确认：

- 连续制作不会在动作播放期间重复提交 `BUILD`，绳子制作完成后会正常进入背包。
- 带放置物的建筑会先等待放置物制作成功，再执行部署；材料被制作消耗后不会再次
  误报“材料不足”。测试营火已成功制作并放置。
- 非玩家真实角色预制体、移动、战斗、跨世界控制器拦截、地图探索组件和独立制作
  能力均正常。

角色选择窗口已在无窗口专用服务器确认：

- 测试玩家为沃尔特、Mod 世界配置仍为“与玩家相同”时，控制器选择麦斯威尔后，
  微光首次生成仍然是麦斯威尔。
- 在游戏运行中从麦斯威尔切换到沃尔特时，旧微光的火把被放到地面，微光以新的
  实体存档重生为沃尔特；随后切回麦斯威尔同样成功。
- 选择写入 `state/companion_character.json`，游戏关闭后仍会保留。

战斗链路已用受控目标在专用测试服务器确认：

- 角色使用标准 `ACTIONS.ATTACK` 动作，攻击动画、冷却和伤害结算正常。
- 目标离开最近 22 格快照范围后仍会继续追踪，不会立刻误报丢失。
- 目标死亡时根据最后一击确认是否由"微光"完成，未确认时不会声称击杀。
- 自动闪避开启时仍能持续攻击并完成击杀，不会在走位和攻击之间反复切换。
- 战斗离玩家超过默认 30 格安全距离时会立即停止追击并上报，随后返回跟随。
- 用户用高优先级 `follow` 覆盖战斗后，攻击目标和战斗意图会立即清除。
- `retreat` 未指定坐标时会返回玩家身边，完成后再上报，不会朝远离玩家的方向跑。
- 击杀后会向 DeepSeek 发送真实战斗结果，并自动返回跟随。
- 玩家角色的技能树选择和已解锁制作配方会同步到同角色"微光"。
- 角色特殊动作白名单、制作绳子和装备切换已通过受控测试。
- 战斗会自动装备可用武器和身体护甲。

## 已知限制

- “独行长路”关闭另一张地图后，"微光"不能在那里继续真实执行任务。
- 地图探索只记录实际经过并观察到的资源，不会凭空读取全图。
- 复杂 Boss 技能编排仍未覆盖所有角色和所有阶段。
- 部分技能依赖角色技能树、特殊物品和动作状态，必须在当前游戏版本中逐步验证。
- 目前只有麦斯威尔拥有本地角色任务预案；其他角色主要依赖 DeepSeek 和研究流程。
